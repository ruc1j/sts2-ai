# Act 3踏破率5%のgoal: フルrunによる事前登録（2026-11-04）

方針を改良し、Act 3踏破率を基準の0.4%（1/271）から5%以上に上げる。採否はフルrunだけで決める。ラボと解析は候補を選ぶ材料にだけ使い、採否には使わない。判定は `docs/EVALUATION.md` に従う。

## 対照と実行条件

- 対照: `astra_ctrl_v23`（136 run）と `astra_ctrl_v24`（136 seed、使えたのは135 run）。方針コードとDLLのハッシュは現在のmainと一致する（`official_agent.py` 61e780f8、`combat.py` 47016145、`Sts2Ai.dll` 592dc541）。

- ゲームv0.107.1、Ironclad、探索100回、`-StopAfterAct 3`、全戦闘でエージェントを使用。ユーザーデータは固定スナップショット `~/.sts2/userdata-pin` を毎回戻す。
- `-AgentMaxCombats` は対照の100に対し、今回は999にする。既存695 manifestの最多戦闘数は23で、どちらの上限にも届かないため、結果は変わらない。
- 実行は `data/run_clear5.sh`（`run_ctrl_accum.sh` と違うのはREPO指定とこの上限だけ）。1本ずつ走らせ、異常で止まる。

## 判定

候補は走行前に凍結し、1回に1つだけ測る。候補ごとにcommitとハッシュを次の表へ追記してから走らせる。

| 段階 | 走らせるもの | 規則 |
| --- | --- | --- |
| 開発用 | 候補のみ（最大135本、約11時間） | 先頭68本で踏破0なら終了。全本で踏破4本以上なら通過 |
| 確認用 | 対照と候補（136 seed×2、約21時間） | 候補の踏破が4本以上で、対照を上回れば採用。それ以外は `docs/EVALUATION.md` に従って保留か不採用 |

- 候補を3つ測って開発用を通らなければ、この方向を閉じて記録する。
- 踏破はresultの `act_3_complete: true` と最終戦ログで確認する。死亡はtraceの `combat_end`（`won=false`、`hp=0`）で確認する。
- 主指標はAct 3踏破数／確定run数。計画数、完了数、不明数を併記する。補助はAct 2・Act 1の突破数と、Queenの削り割合。
- 外部要因の停止は未完了として別記し、同じseed・版・条件で別tagへ再実行する。候補に由来する例外や停止は信頼性の悪化として数え、母数から消さない。

## 数字の根拠

Fisher検定（両側α=0.05）で新規136 runと1/271を比べると、有意になるのは4本以上である。真の踏破率が5%なら通過確率は91%、0.4%のままなら約0.2%。3%なら約59%で、3%程度の改善は安定して検出できない。68本で踏破0になる確率は、真の踏破率が5%でも約3%である。開発用の本数は135本で、上の計算より1本少ない。

## 候補選びの経緯（実機なし、採否には使っていない）

解析は `bosslab/results/pilot_diag.md`、`pilot2_result.md`〜`pilot6_result.md`。値はすべてcombat.py内で、実機の勝敗ではない。

- モデル内のmainはQueen勝率1.7%、Insatiable勝率40〜45%で、実走（1/59、47%）に近い。
- 上限の分解（Queen勝ち/59、Insatiable勝ち/30）: main 1・12、エネルギー+1 3・24、全札強化 5・24、両方 8・29、基本札半減 2・16、Strength札3枚追加 2・17、ターン計画 1・未実行。探索1000回は4入場で差なし。
- 実走しないと決めたもの: 負けロールアウトからimmediateも外すv2（モデル内で悪化）、HEALをSMITHへ置き換える案（モデル内で悪化、CODEWIKIの過去2回と同じ向き、ただし反事実のHP計算は悲観的）。
- 開発用の枠が3つしかないので、正の向きの部品をC1へまとめた。部品は負けロールアウトの進捗（v1）、合法手フォールバック、DEMON_FORM・RUPTURE・CRIMSON_MANTLE・INFLAMEの報酬とショップの優先、DEMON_FORM序盤出し。4枚のどれかが提示されたrunは196/272。

C1は回帰テストの10件と衝突する（RUPTUREを燃料なしで取らない、ブロック不足の補充を優先、Perfected Strike軸など）。テストは書き換えず、このまま測る。戦略の変更が開発用を通らなければ、これらのpinは維持される。真の踏破率が5%に届く見込みの根拠は、モデル内にもない。全部品を足した状態の確認（D8）も未実施である。

## C2の候補と経緯（2026-11-04）

C1に対する変更は1点で、報酬のRUPTURE優先に燃料条件を戻す（ショップは据え置き）。根拠は `bosslab/results/pilot10_result.md`。C1と対照をseedで組むと、報酬経由で燃料なしのRUPTUREを持ったrunは、到達点が改善0、悪化5（n=10）だった。C1の結果を見て作った変更なので、開発用の通過だけでは採用の根拠にならず、確認用が必要である。

見送った案: engine優先をブロック不足で止める案（`c689773`）。C1のengine採用251件のうち227件で`_block_starved`が真で、踏破3本の採用5件もすべて対象になり、C1の土台を消すため走らせない。基本札の削除を優先する案は、踏破2本のショップ判断に触れるため見送った。

### C2走行中の注意（2026-11-04、63本時点）

同じseedで方針の判断が同じなら、runは決定論的に同じ結果になる。C2の63本のうち55本は、C1と到達点、勝利数、結果が一致した。`895C061BBB`の踏破は、判断列まで完全に一致した。

したがって、C2の開発用は135本の独立した標本ではない。C1の踏破3本は、変更に触れなければそのまま再現する。通過の4本は「C1の3本＋変更で分岐したrunの1本」で達成しうるので、C2が通っても、C1からの上積みは分岐したrunの中で読む。この性質があるので、未知のseedで両版を比べる確認用が判定の本体になる。
