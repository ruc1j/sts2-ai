- 踏破率（1 / 136）は低すぎて、このパネルでは測れない。Wilson区間は全run基準で0.1〜4.0%で、数百runを足しても幅は縮まりにくい。主信号は踏破率ではなく、Queen戦の終局状態（Queen削り割合、Amalgam撃破、死亡ターン）にする。踏破率は補助として、分母と留保つきで記録する。
- Queen戦に到達するrunは、1 runあたり約0.24（33 / 136）である。1 runの平均所要時間は281秒（Act 3まで進んだrunは388秒）で、1時間あたり約12.8 runである。
- Amalgam撃破率58%の95%区間の幅は、Queen戦33 runで±16pp、66 runで±11pp、100 runで±9pp程度になる。
  - 66 runにするには、新しいrunが約136本（約10.6時間）必要である。
  - 100 runにするには、新しいrunが約280本（約22時間）必要である。
- 第2段階の実機は、新規seedで136本程度を追加する案を第一候補にする（既存のQueen戦33 runと合わせて66 run程度）。開始前に日時と本数を決める。

## Block札追加の対照実験とBの扱い（2026-10-31）

目的は、パネルで見えた「Skillが少ないデッキほど削りが低い」という相関が、Block札を足すと変わる因果かどうかを、ラボの対応あり比較で確かめることである。事前登録は `bosslab/results/act3_blk_prereg.md`、凍結は `act3_blk_freeze.md`、判定は `act3_blk_judgment.md`（ブランチ `bosslab`）にある。

### 判定

| 項目 | 判定 | 要点 |
| --- | --- | --- |
| C: 入場状態の書き戻し | 採用（条件つき） | 同じ12 specで一致が10/12から11/12に増えた。実機ビルドは1回。BLESSED_ANTLERのDazedは直らず、このspecは除外を続ける |
| A: add4（SHRUG_IT_OFF 2枚＋FLAME_BARRIER 2枚を足す） | 不採用（「効かない」） | 確認用でΔshave −2（候補優3、base優5、同値4、p=0.727）、Δfp −3.8、Δwin −1（1→0）。開発用と向きは一致するが、削りで優ることを示せなかった |
| A: add2（各1枚を足す） | 保留（測定の対象外） | 開発用の発火が3/6組で閾値の4組に届かず、事前登録の規則に従い確認用を流さなかった |
| B: 報酬選択の方針をフルrunで確かめる | 保留（実施せず） | 前提のAが「効かない」ため、事前登録した条件（Aが「効く」の場合だけ）に従い行わなかった。報酬選択の方針そのものの採否は判定していない |

### 結果の数字（Block札使用の発火は、addアームがbaseより多く使った組）

- 開発用（6 spec）: add4の発火 4/6組、Δshave −5（候補優0、base優5、同値1、p=0.062）、Δfp −12.5（42.4→29.9）、Δwin 0。
- 確認用（12 spec）: add4の発火 10/12組、Δshave −2（候補優3、base優5、同値4、p=0.727）、Δfp −3.8（38.8→35.0）、Δwin −1。生存ターンは6.58から7.17へ延びた（add優6、base優3、同値3）。
- 足した札は実際に使われており（確認用で10/12組）、使われなかったことが原因ではない。使われたうえで、Queen削りと総火力/ターンは増えなかった。

### 留保

- 標本が小さい。開発用は6組（条件を満たすspecが18件しかなく、確認用の12組を優先して確保した）、確認用は12組、各アームのrng_offsetは1つだけである。確認用のp=0.727は、削りの有意差を示せなかったという意味で、差がないことの証明ではない。
- 足したのはSHRUG_IT_OFFとFLAME_BARRIERの2種（未強化）だけである。ほかのBlock札、強化済みの札、枚数の違いについては、何も言えない。
- ラボの絶対値は実走と一致しない。書き戻しは足した札が山札の先頭に置かれる副作用を避けるため、この実験では使っていない。FORGOTTEN_SOULを持つspec（確認用に3件）は、敵HPが数ポイントずれた状態で入るが、全アーム共通なので対応ありの比較では打ち消される。
- 確認用の生存ターンは延びており、Block札が体力の消耗を遅らせた可能性はあるが、勝ちは増えず（1→0）、削りも増えなかった。Skill枚数が少ない群の削りが低いというパネルの相関は、Block札の枚数の因果としては支持されなかった。デッキの強さや到達までの経路との交絡が残る見方のままである。
- 条件6（比較の完全性）の読み替えは、開発用の結果を見る前に追記して固定した。判定規則の他の条件は変えていない。
