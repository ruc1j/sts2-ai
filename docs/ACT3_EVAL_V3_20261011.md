# 確定討伐の強制条件の比較計画 v3

実行条件の原本は`data/astra_eval_v3_plan.json`。`docs/EVALUATION.md`に従う。結果を見た後にseed・反復数・版を変更しない。

## 比較するもの

- 仮説: `lethal_direct`が「倒しても致死が残る討伐」と「主敵が生きている間の取り巻きだけの討伐」を強制せずrolloutへ任せると、踏破率または到達度が改善する。
- 変更の種類: 判断の変更2件の組合せ。どちらも`lethal_direct`の強制条件で、同じOVICOPTER戦の失敗から見つかった。
- 対照`5b79fc8`（v2の候補）、候補`680bfb4`（ブランチ`eval-v3-candidate`）。候補は`ad7acb7`（致死被弾の手番の制限）に`4a95665`（取り巻きだけの討伐を強制しない。Torch Head・Kin Followerと致死回避は例外）をcherry-pickしたもの。差分は`official_agent.py`の2か所と回帰テストのみ。`combat.py`とModのDLLは同一。
- 計画は実走前に候補を`ad7acb7`単独から差し替えた。v3の結果はまだ1件も出ていない時点での変更。
- 局所検証: A972 v2候補のOVICOPTER戦seq214・215がShrug It Offに変わる。68AC v2候補のOVICOPTER戦で卵を倒していた7局面の大半がOVICOPTERへの攻撃に変わる。過去traceでこの条件に当たる`lethal_direct`は重複除去後101行（敗北戦闘54行）。手札の防御を使えばその手番を生き残れた行は敗北戦闘で20行。現行mainで101行を再生すると、条件外の討伐が残った行は0件。

## 固定条件と終了条件

- v2と同じ条件（ゲームv0.107.1、Ironclad、Ascension 0、探索100回、全戦闘エージェント、Act 3まで、userdata-pin復元）。
- 開発用7 seed: A972EACCB8（この修正を見つけたseed）とv2の確認用6 seed（7FCFED219F、EB97217329、D839F5F1C8、C510D86949、68AC111D81、D0E3C14EFE）。いずれも結果を見ている。
- 確認用6 seed: `sts2-ai/eval-20261011/v3/confirmation/{i}`（i=1..6）のSHA-256の先頭10桁。A654E6987F、11E4FCE85A、DACBAF33B5、689AEB7CBF、3FD2827979、41D827E38D。過去のファイル名にないことだけを確認した。
- 開発用seedの対照は、v2候補の記録を再利用する。v2候補とv3対照はcommit・ソースとModのハッシュ・実行条件が同一で、`docs/EVALUATION.md`の「条件とハッシュが揃った既存記録」に当たる。同一版・同一seedの再走は過去にも同じ結果になっている（v1候補とv2対照のN8・D6・A972・9B3・4DE）。
- 新規の実走は19 run（開発用の候補7、確認用の両版12）。1 runの上限1800秒、パネル開始から14400秒。
