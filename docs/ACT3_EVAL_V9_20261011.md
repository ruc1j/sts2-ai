# コスト0のRageの打ち順の比較 v9

実行条件の原本は`data/astra_eval_v9_plan.json`。`docs/EVALUATION.md`に従う。結果を見た後にseed・反復数・版を変更しない。

## 比較するもの

- 仮説: Rageの防御優先の分岐をコスト1以上の場合に限ると、コスト0のRageが攻撃より先に打たれ、Rageのブロックを失わずに済み、踏破率または到達度が改善する。
- 変更の種類: 判断の変更(単独)。
- 対照`e55514d`(v8候補と同じコード)、候補`58758bd`。差分は`official_agent.py`のRage分岐1か所と回帰テストのみ。`combat.py`とModのDLLは同一。
- 発見の経緯: v4候補B7BC1DD2A8のDECIMILLIPEDE戦seq207〜210で、Iron Wave、Defend、Defendの後に攻撃の残らないRageを打った。
- 局所検証: 実ゲームのRageはv2〜v8で観測した163枚すべてコスト0。`rage_defense_direct`が発火した165ターン(重複除去)で、Rageより前に打った攻撃が95回、Rageを打たずに終えたターンが25回あった。既存テストはすべてコスト1のRageを想定しており、変更後も通る。

## 固定条件と終了条件

- v8と同じ条件(ゲームv0.107.1、Ironclad、Ascension 0、探索100回、全戦闘エージェント、Act 3まで、userdata-pin復元)。
- 確認用A 16 seed: v8の確認用seed。対照はv8候補の記録を再利用する(同一commit・ソースとModのハッシュ・実行条件)。v8の結果は見ているが、この変更の発見・調整には使っていない。再利用する記録が未確定のseedは比較から除き、再実行しない。
- 確認用B 8 seed: `sts2-ai/eval-20261011/v9/confirmation/{i}`(i=1..8)のSHA-256の先頭10桁。AE8BA0F877、6F6F2E036C、76E9F731A3、E823334490、87FE5FD8A7、364D012944、ED1CEF9466、2066D9D9DF。過去のファイル名にないことだけを確認した。
- 新規の実走は32 run(Bの両版16、Aの候補16)。Bを先に、seedごとに両版を続けて実行し、先に実行する版を交互にする。1 runの上限1800秒、パネル開始から10800秒。v8の完了後に開始する。
