# 戦闘をまたぐレリックのカウンター

## 仮説・分類

Pen Nib、Nunchaku、Tuning Forkは取得後の使用回数を戦闘間で持ち越す。モデルは戦闘履歴の回数を使っていたため、発動位置がずれる。ゲーム再現の正しさの修正であり、カード優先順位や評価関数は変更しない。

## 実装・観測の根拠

- 対象はインストール済みゲームv0.107.1。逆コンパイルした`PenNib.AttacksPlayed`、`Nunchaku.AttacksPlayed`、`TuningFork.SkillsPlayed`はいずれも`SavedProperty`。`DisplayAmount`は演出中に別の値を示すため、保存対象のプロパティを読む。
- Pen Nibは`BeforeCardPlayed`で攻撃回数を進め、10回目の解決だけを倍にする。`CardModel.OnPlayWrapper`は複数回使用の各解決で`BeforeCardPlayed`と`AfterCardPlayed`を呼ぶ。
- `astra_goal_r7_N8CQ4ZKP2W`ではseq91でPen Nibを所持して戦闘を開始し、seq106の攻撃回数8でByrdonis戦を終了する。次のPhrog Parasite戦では戦闘内カウンターが0へ戻るが、レリックの8回は残る。
- seq115は戦闘内攻撃1回＋持ち越し8回で、次のStrikeが10回目。旧モデルの敵HP45に対しゲームは39。seq133は戦闘内9回＋持ち越し8回なので次は18回目で、旧モデルHP4に対しゲームは12。

## 修正と検証

Bridgeの観測とtraceに`player.relic_counters`を追加し、レリックごとの実値をモデルへ渡す。新しい値がない旧traceでは従来の戦闘内回数による近似を残す。レリックごとの回数を独立に更新し、ターン終了時も保持する。Pen Nibは複数回使用で10回目をまたぐ場合、該当する解決だけを倍にする。

回帰テストは、持ち越し・値0の優先・次のカードへの更新・ターン終了・レリック間の独立性・単体攻撃/ランダム連撃/全体攻撃と複数回使用を確認する。対象2モジュール785件と全823件が成功。Modは.NET 9でビルド成功、警告0・エラー0。

記録から復元したカウンター9と7をそれぞれseq115、133へ与えた局所再生では、敵HP39、12が実ゲームと一致した。これは新Bridgeでカウンターを実測した結果ではないため、次の実走で新しいフィールドの出力と一致を確認する。踏破率への効果は未測定。
