## 2. 各アームの判断変化の見込み（開発用135のうち）

- S1/S2: 強化が1枚以上ある run が82/135（Insatiable入場までに強化があるrun）。強化先が変わるので、その82 seedが変わる。C1の踏破3本も強化先が変わる（「消える」ではなく「変わる」）。
- S3: 直前の戦闘でポーションを使ったrunは17/135だけ。加えて入場時のポーション本数が C1 2.45本・対照2.56本とほぼ同じで、温存しても増えるのは最大11本（51入場で）。モデルでも変化0。
- S4: 削除が可能なのに買い物を優先したshop行が260件、101/135 seed。ただしモデルでは Insatiable が悪化した。

## 3. S5（Insatiable専用の報酬）は閉じた筋

`CODEWIKI.md:471-478`（2026-10-11、閉じた筋）に、`BOSS_CARD_AXES` の INSATIABLE 軸へ Inflame・Demon Form を足しても変わるのは8判断、Demon Form の格付け C→S で9判断、強ブロックを軸から外しても13判断/9 seedと記録されている。同じ案は繰り返さない。

## 4. S1のDLL変更（実装はしていない）

- 変更箇所: `official_mod/RestBridge.cs` の `SmithCardSelector.Score(CardModel card)`。
  現在は RUPTURE 1200（Act3ボス近傍）、強ブロック 1000+、PERFECTED_STRIKE/HELLRAISER 700、INFLAME 640、既定300。
  S1では「強化でダメージが増える攻撃札」を先頭にし、増分の大きい順に並べる。C#側に `combat.py` の
  `CARD_UPGRADE_DAMAGE` と同じ表（Bash 2、Squash 2、Tear Asunder 2 など）を持たせ、攻撃札は `1000 + 増分`、
  それ以外は現行順にフォールバックする。
- ビルド手順: `pwsh -File ./build_official_mod.ps1 -GameDir '<game dir>'` →
  `official_mod/bin/Release/net9.0/Sts2Ai.dll` を生成し、sha256 を manifest に記録。Python側の変更は無い。
- 影響範囲: SMITH の選択（C1の前身パネルで777回）すべて。DLLが変わるため、対照は現行DLLのまま。

## 5. 留保

- 入場状態はC1のデッキで、Insatiable 30/82・Queen 21/21の標本。30件での勝ち数の差（+2）は小さく、乱数1本。
- S1は「強化の枚数を増やさず、対象だけ変える」アーム。実機で同じ枚数を維持できるのは、SMITH回数が同じだから。
- S4の削除数は、入場デッキから基本札を最大で「見送った削除機会」の数だけ抜く近似で、ショップの順序そのものは再現していない。
