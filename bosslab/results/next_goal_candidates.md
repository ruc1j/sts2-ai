## 補足

- 1 と 2 は束ねる：先に PenNib 反映（改修・ビルドのみ、dsh 側で実施可）を入れ、そのビルドで 2 の新確認用 12 spec を採れば、カウンタ起因の忠実性不一致を含まない集合で H3a/H3c を測れる。2 だけの新 spec を旧 build で採ると PEN_NIB 不一致が again 残る。
- 忠実性の残り 5 件のうち Whetstone/NewLeaf（0007 の deck 漂移）と 0011 の敵入室 HP は、配対比較で両腕共通なので判定には効かない（`act3_confirm4_fidelity_causes.md`）。これらを直すすべは goal の判定と直交するので、優先は 1（カウンタ）＞ 適宜（残 2 種は次 build で spec を採り直すときにまとめて直す）。
- 実機 run は leader、dsh 側はゲームを起動しない。判定規則（apply_hybrid_rule.py）は 1 回のみ実行が約束で、2 の H3 用に新しい dev/confirm 集合を積むときは同じ規則（commit 4693f2e）を新しい集合に対して別枠で 1 回使う。

## dev5 実測後の順位見直し（2026-10-29、確認用の結果は未反映）

dev5_swap（12組）の実測を反映。確認用 confirm5 は走行中で、その結果はここに入れていない。

- 順位の柱は変えない。ただし 2（H3a・H3c の実機比較）の「効く見込み」を「高」から「低〜中」へ下方修正する。
  dev5 で H3a は `Δshave = 0`（候補優5/base優5/同値2）、H3c は `Δshave = +1`（候補優6/base優5/同値1、p=1.0）
  だが両者 `Δfp < 0`・`Δwin < 0` で 4693f2e の条件を通過せず、調整 0 組合せで凍結（`act3_h3_freeze.md`、92569ca）。
  前提 G（発火 H3a 11/12・H3c 12/12）は満たす。confirm5 が dev5 と同じ向き（中性〜マイナス）なら、Queen 戦闘で
  殴り先を変える方針変更は不採用に寄る。
- 新しい余地「Amalgam をより早く倒す」は Queen 戦闘内では薄い。base 48組（dev2/dev3/dev5/confirm4）の解析で、
  倒せた組と倒せなかった組の攻撃カード数と開始エネルギーは同程度、使える攻撃ダメージの取りこぼしも 47組中 1 ターン。
  差がともなうのは防御（Block）カード数と開始強化の有無で、これは Act 3 の報酬選択・昇格（フル run）で決まる。
  lab は入場固定でデッキを作れないため、固定入場 1 戦闘の lab では作り出せない余地。詳細 `act3_amalgam_kill_speed.md`。
- 含意: 2 の判定が confirm5 でも中性なら、3（Act 3 フル run パネル、踏破率の実測）の重み上がる（Amalgam を早く
  倒す余地が実在するならフル run 側で測る）。1（PenNib 反映）は忠実性改善で不変。4（Act 2 Shrug）と 5（TEST_SUBJECT
  標本）は本 goal と独立で順位そのまま。confirm5 の結果が出たら最終順位を更新する。
