# Act 3 殴り先 hybrid（H1/H2）の判定規則（結果を見る前に事前登録）

dev2 base/H1/H2、および新規確認 panel confirm4 の結果を読む前に、採否の規則をここに固定する。
以後この条件は動かさない。判定は `docs/EVALUATION.md` の「採用・保留・不採用」に追随し、ラボで測定
できない Act 3 踏破率に代わる進捗の代理指標で判定する。

## 集合の役割（EVALUATION.md §固定パネル / §実験の前に）

- **dev2**（order-seed 既知、base 完了・H1/H2 走行中）= 開発用。ここで H1/H2 のどちらを確認 panel へ
  進めるかを選ぶ（下記の「候補選定規則」）。同じ集合を何度も見て調整した後は開発用として扱い、最終
  採否の証拠には使わない。
- **confirm4**（新規 12 組、used.speclist と重複なし、開手札ランダム付与系と RELIC.PAELS_CLAW（Goopy）除外
  済み）= 確認用。
  ここで最終の採用・保留・不採用を決める（下記の「採否規則」）。候補の結果を知らずに選定済み。

EVALUATION.md の採否は「開発用・確認用の両集合で改善」を要求するため、最終判定は両集合の向きが揃って
初めて確定する。片方だけでの改善は保留どまり。

## 共通の測定手順（両集合で同一）

比較は `bosslab/tools/analyze_bosslab.py --compare-pair LABEL=BASE_DIR:CAND_DIR`。base と候補を **同じ
entry（spec_id と rng_offset）で配対**し、entry ごとに候補優/base 優/同値を数える（EVALUATION.md の
到達点同値の最終戦を同じ開始状態で見ると同じ趣旨。配対なので開始 HP・deck・relic・ポーションは共通）。

主信号（2 つ）:
1. **Queen 削り割合** = 1 − (死んだ時点の Queen 残 HP / Queen 最大 HP)。Queen 撃破・勝利時は 1.0。EVALUATION.md §到達点同値の最終戦の進捗そのもの。
2. **総火力/ターン** = (Queen と Amalgam が失った HP 削除量の合計) ÷ (その腕自身の生存ターン last_observed_turn)。定義は §5-2 と同一（trace の逐次 HP 減少の総和、盤面から消えた敵は最大 HP まで削った扱いで overkill は足さない）。

補助・ゲート（採否の必要条件、EVALUATION.md §到達点同値で次の指標）:
- **総火力/ターンが base を下回らない**（候補の集合平均 ≥ base の集合平均）。これは queenfirst が削りで
  3 集合すべてに勝ったのに総火力/ターンで落としたことを踏まえたゲート（下記の較正参照）。
- **勝ちが base を下回らない**（候補の勝数 ≥ base の勝数）。ラボの勝ちは Queen 撃破で確定。
- 補助（判定には使わないが併記）: Queen のみの火力/ターン、Amalgam 撃破、死亡ターン（長いほど良い）、失った HP。

符号検定（EVALUATION.md §到達点同値の進捗と flip 検定と同じ）: 同値を除いた配対で base 優 b 件・候補優 c
件とし、精密二側 p = `mcnemar_exact_p(b, c)`。削り割合の主信号で計算し報告する。p の閾値は下記の採否規則
で事前に固定し、結果を見て後から引き下げない。

注: confirm4 の idx11（ROYAL_POISON 所持）は、HP 修正（コミット 927f26f）後も入場 HP の絶対値は元 run
基準（予想 90）で、ラボの実走一致は 8/12→9/12 相当になる。ただし判定は同じ entry の base 候補間の**差**で
行うので、この絶対値のずれは配対比較に効かない（両腕同じ entry）。絶対値の実走一致とは別に評価する。

## 候補選定規則（dev2 の結果で H1/H2 のどれを進めるかを決める）

各候補 C ∈ {H1, H2} について、dev2 で base と配対比較し、次を計算する:
- `Δshave_C` = (C 優の配対数) − (base 優の配対数)（同値は除く）
- `Δfp_C` = mean_C(総火力/ターン) − mean_base(総火力/ターン)
- `Δwin_C` = C の勝数 − base の勝数

候補 C が「条件充足」であるための条件（すべて）: `Δshave_C > 0` かつ `Δfp_C ≥ 0` かつ `Δwin_C ≥ 0`。

- **両候補が条件充足**: `Δfp` の大きい方へ進める。差が 0.5 HP/ターン以内なら同帯として `Δshave` の
  大きい方、それでも同値なら **H1**（削り済み優先の従属則で、脅威型の H2 より挙動が限定的）を優先。
  決定は乱数に依存しない。
- **片方だけ条件充足**: その候補を confirm4 へ進める。
- **どちらも条件充足でない**: hybrid を進めない（両候補を落とす）。confirm4 には base に対して dev2 で
  最も `Δshave > 0` を満たす候補を 1 つだけ進め、採否規則で 不採用 を確定する（充足候補が無い場合の
  記録用。hybrid 機構自体を却下するかは採否規則の「両候補同じ向き」条項で決める）。

## 採否規則（confirm4 = 確認用集合で最終判定）

選ぶ候補を C*（dev2 で選定、単一）。confirm4 で base と配対比較した上で、EVALUATION.md の順序で判定する。

- **採用**（すべてを満たす）:
  1. C* が confirm4 の主信号 削り割合で `Δshave > 0`（候補優 > base 優）、かつ dev2 でも `Δshave > 0`（両集合で同じ向き＝機構が頑健。EVALUATION.md §採用）。
  2. 両候補 H1/H2 の **削り割合の向きが dev2 で同じ**（ともに `Δshave > 0`）。H1 が良く H2 が悪い等の割れは機構頑健でなく採用しない。
  3. confirm4 と dev2 の両方で `Δfp ≥ 0`（総火力/ターンが base を下回らない）。
  4. confirm4 と dev2 の両方で `Δwin ≥ 0`（勝ちが base を下回らない）。
  5. confirm4 の削り割合の配対符号検定で精密二側 p ≤ 0.05。
  6. 未解消の信頼性の悪化が無い（配対不能 entry が無い＝12 組すべて配対、lab 例外や通信障害が無い）。
  → ラボは Act 3 踏破率を測定できないため、採用時の記録文言は EVALUATION.md の「最終戦の進捗改善として
  採用、踏破率・到達点の向上は未確認」を用いる。

- **不採用**（いずれか）:
  - C* が削り割合で dev2・confirm4 の両集合で `Δshave ≤ 0`（悪化または同値）。EVALUATION.md §不採用（両集合で悪化）。
  - 削りが悪化して、かつ 総火力/ターン も base を下回った（主信号 2 つとも劣化）。
  - 前提・実装の誤りが実測で判明（例: HP 修正後も fidelity の一致が取れない、lab 例外、配対不能）。
  → base の継続。理由と対象範囲を残す。

- **保留**（採用でも不採用でもない中間）:
  - 削り割合は確認用で改善したが、火力/wins/両集合の向き/p≤0.05/頑健性（両候補同じ向き）のどれかを
    満たさない。
  - H1 と H2 の向きが dev2 で割れた（採用の頑健性条項を満たさないが、片方は局所改善）。
  - 配対不足・欠測・同値（`Δshave = 0`）で主信号がどちらにも傾かない。
  → 次の必要な証拠（集合追加・片候補のみ再走・fidelity 一致の確認等）を具体的に書き、1 配対でも改善へ
  傾いた組は再検証候補として残す（EVALUATION.md §保留）。比較不能を 0 で埋めない。

## 較正参照（既存 queenfirst、開発集合・HP 修正前の DLL）

同じ entry 配対で base 比の分布（dev2・confirm2・confirm3 の 3 集合、36 組プール）。採用でなく **参考**
であり、confirm4 の結果ではない。

| 指標 | base | queenfirst 候補 | 向き |
| --- | --- | --- | --- |
| Queen 削り割合（集合別） | 0.273 / 0.282 / 0.333 | 0.406 / 0.377 / 0.422 | 候補優（3 集合同向き、プールの精密 p 0.009） |
| 総火力/ターン（集合別） | 37.5 / 36.8 / 38.7 | 32.9 / 31.1 / 35.9 | **候補が 3 集合すべてで下回る** |
| 勝数（プール） | 3/36 | 2/36 | 候補が 1 減 |
| Amalgam 撃破（プール） | 22/36 | 3/36 | 候補が大きく減 |

この分布から、削り割合だけでは採否を決めず、総火力/ターンが base を下回らないことと勝ちをゲートにした
理由が固定される（queenfirst は削りで全集合に勝ったが火力と勝ちで落とした＝保留以上には進まなかった）。
H1/H2 はこの火力低下を回避する設計（Amalgam を opportunistic に殺し、Queen へ通す火力を保つ）なので、
上記の火力/wins ゲートを通るかを dev2 で見て候補を選ぶ。

## 固定と事後変更の禁止

- この規則は dev2/H1/H2、confirm4 の結果を読む前にコミットし、以後同じ commit に対して条件を変えない。
- 判定に使わない補助指標の追記（Queen のみの火力/ターン等）は採否を変えない。指標・閾値を結果後に追加・
  変更した場合は、変更日時・理由・時点で確定済みの結果を別記し、新条件では新規の確認用集合で再確認する
  （EVALUATION.md §実験の前に、指標の事後追加）。
