# H3a/H3c の「第一手が変わる組」を既存 base 実測から数えた（実機なし）

採否規則案の G 条（発火率の前提）が要求する `firing_C ≥ 4/12` が妥当か、dev2 と confirm4 の**記録済み base
（queenfirst）パネル**の各 trial 第一手観測から、H3a/H3c 相当の規則を機械的に当てはめて数えた。実機は走らせない。
再現は `python3 bosslab/tools/h3_firstdecision_diff_model.py <base panel dir>`。

## 結果

| base panel | H3a が第一手を変える組 | H3c が第一手を変える組 | base が既に Amalgam を第一手で狙った組 |
| --- | --- | --- | --- |
| dev2（12） | 7/12 | 0/12 | 5/12 |
| confirm4 base（12） | 5/12 | 0/12 | 5/12 |

- H3a（open turns ≤2）: turn1 の第一手は常に.turn 窓に入る。Amalgam が生存・単独攻撃可能で、base が既に
  Amalgam 単独指定で無い組で反転。dev2 7、confirm4 5。**両集合で 4/12 を上回る**。
- H3c（danger、期待被ダメ > 0.5×生存HP）: 第一手時点の期待被ダメは 13〜18、player HP 44〜114（0.5× =
  22〜57）で、どの trial でも 0.5×HP に届かず **0/12**。第一手では発火しない。

## 4/12 は妥当か（結論）

- **H3a には妥当**（5〜7/12 で余裕を持って通過）。同時に、confirm4 で一度も発火しなかった H1/H2 は第一手差分
  0/12 なので、4/12 の閾値は「候補が発火せず base と同一」の測定を保留に回して採否を出さない目的にちょうど合う
  （H1/H2 を 4 未満で弾き、H3a を通す）。0 件を「不採用」でなく「保留」に落とす設計も、この 0/12 の実測で意味を持つ。
- **H3c には第一手差分だけでは不適**。H3c は danger 起点で、第一手（turn1・HP 高・被ダメ 13〜18）では発火せず、
  HP が削れた中盤以降に発火する可能性が高い。第一手差分を 0 と数える代理指標だと、実際に中盤で発火しうる H3c を
  「発火 0=測定不能」と誤判定する。よって G 条の発火は第一手だけでなく全ターンの行動差分（arm が作動した
  意思決定の数）で測るべきで、4/12 もその広い発火イベント数に対する閾値として維持するのが妥当。正確な H3c の
  発火率は、実装済みの H3c を実機で流した panel の行動差分で測り直す（`bosslab_turn_diff.py` の配対差分で可）。

## モデルの粗さと前提（数値の信頼性）

- 「単独攻撃可能」= 第一手観測に Amalgam（slot amalgam）を指す合法カード行動が存在（target_id は
  obs.enemies への 1-based。AoE の target_id null は「Amalgam 集中」に数えない）。攻撃か skill かは見ていない。
- H3c の danger は、block を引かない素の期待被ダメ vs player HP。実際の agent は block を考慮し、HP が削れた
  後続ターンの danger はこの表に現れない（第一手のみ検査）。
- base が既に Amalgam 単独指定の 5/12 は、規則が同じ手を選ぶので反転に含めない（保存的）。
- dev2 で 1 件・confirm4 で 2 件、第一手に Amalgam 単独攻撃の合法手が無い trial があり attackable=False で
  反転 0 にカウント（Amalgam が射程外／攻撃札が手で取れない）。実走由来なので妥当。

したがって **4/12 は H3a 判定の閾値として支持される**が、H3c の前提には第一手差分でなくターン横断の発火
イベント数を当てる、という点を実測で補正しておきたい。
