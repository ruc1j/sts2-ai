# Act 3 フルrunの介入候補3領域スキャン（T47、2026-10-29）

## T48 検証（先読み）: 計器の正しさ、T47 の結論は変わるか

**変わる。** T47 の「Skill 型＝Block」代用は過大計上だった。報酬に出た Skill 型 655 枚のうち、実際に Block を持つのは 279 枚だけで、残りは Block を持たない Skill（全体弱体・ドロー・エネルギー系）376 枚だった。実 Block に絞ると、T47 が見せた「低 Skill run で Block を 98 枚捨てた」規模は縮み、しかも「低 Skill run ほど Block を避けている」は **採用率では再現しない**（低 Skill 群 44.4% に対し他群 49.0%、差は 4.6pt で run 別の提示 2〜10 枚のばらつきの範囲）。低 Skill run が Block を採った枚数が少ない主因は、出た Block 枚数そのものが少ないことで、エージェントの選り好みの差ではない。

一方、余地が完全に無くなったわけではない。報酬で Block を 279 枚受け取り 129 枚採り、150 枚を採らなかった（内訳: 他の札を選んだ 114、報酬ごと全体を飛ばした 36）。うち 114 枚は Block を差し置いて別の札（Attack/Power/no-Block Skill）を採た選択で、ここが実体のある取舍。順位（報酬選択 > 昇格 > ポーション）と第一候補は据え置きだが、報酬選択の余地の大きさ T47 の「大」は「中」へ引き下げが妥当。実機で測りやすさとリスクの判定は T47 のまま。

T47 本文（下の節）は Skill 型全体で数えた初出のまま置いてある。実 Block での読み替えは本節による。

### 1. 報酬に出た Skill 型を Block あり/なしに分けた数え直し

Block の判定は、run 全体の手札で `vars` に `Block`/`ExtraBlock` を持ったことのある card id で行った（報酬提示の札には `vars` が無く、同じ id が手札に出た記録から型を引く。提示された Skill 655 枚はすべてこの表で Block/なし に分けられ、型不明は 0 枚）。

Block を持つ札だけで採った/捨てた:

| 区分別 | 出た枚数 | 採った | 採らず |
| --- | --- | --- | --- |
| Block あり Skill | 279 | 129 | 150 |
| Block なし Skill | 376 | 66 | 310 |
| 型不明 | 0 | 0 | 0 |

T47 が捨てたと数えた Skill 460 枚のうち、実 Block は 150 枚だけだった（残りは Block を持たない札）。Skill を採った 195 枚のうち Block は 129 枚。

### 2. 出た枚数で割った採用率（run 別の出方の差を除く）

Queen 戦入場デッキの Skill 枚数の中央値 10 を境に、Block 札の「採った／出た」率を比べた。低 Skill 群（9 run）と他群（Queen 戦到達のうち 24 run）。

| 群 | run 数 | 出た Block | 採った Block | 採用率 |
| --- | --- | --- | --- | --- |
| 低 Skill 群（<中央値10） | 9 | 54 | 24 | 44.4% |
| 他群（>=中央値10） | 24 | 143 | 70 | 49.0% |

低 Skill 群の run 別採用率は 25〜100% と広く、run あたりの Block 提示も 2〜10 枚でばらつく。4.6pt の差はこのばらつきの範囲で、「低 Skill run ほど Block を採らない」という傾向は採用率では確認できない。枚数の差は出た Block 枚数（低群は 1 run 平均 6 枚、他群も同程度）とrunごとの偶然で説明がつく。T47 の「低 Skill run に余地が集中」は計器の作り出す見かけだった。

### 3. Block 札を捨てた理由の内訳（他の札を選んだ／報酬を全体飛ばした）

報酬は 3 枚提示から 1 枚採るか、全部飛ばす（trace では `card_reward_alternative`・`option_id:"Skip"`、採る札の無い記録）か。Block を採らなかった 150 枚（45 run 合計）を分けた。

| Block を採らなかった理由 | 枚数 |
| --- | --- |
| 別の札（Attack/Power/Skill）を採った | 114 |
| 報酬ごと全体を飛ばした | 36 |

大半（114）は Block を差し置いて他の札を選んだ選択。報酬ごと飛ばした 36 枚は、そもそも採る前提が崩れたケースで、Block を「避けた」とは言い切れない。実体ある取舍として数えるべきは 114 枚。

## 結論（3領域の順位）

対象: `astra_ctrl_v23` の Act 3 進入 45 run（うち Queen 戦 33）。trace からの数だけ。因果は主張しない。
軸は 余地の大きさの見込み・実機で測りやすさ・リスク。

| 順位 | 領域 | 余地の大きさ（見込み） | 実機で測りやすさ | リスク |
| --- | --- | --- | --- | --- |
| 1 | 報酬選択（Skill/Block を採る） | 中（T48 検証前はこの節の数で「大」だったが、実 Block では中。上の T48 節参照） | やや難しい（報酬選択は run 内。フルrun panel でしか測れず、Queen 戦 lab では測れない。clear 率が非常に低く雑音大） | 小（方針変更のみ、既存の Queen 戦 lab 判定は不変） |
| 2 | 昇格（強化/回復の振り分け） | 小〜中 | 同じく難しい（campfire 選択も run 内） | 小 |
| 3 | ポーション使用 | ほぼ無し | 最も容易（Queen 戦闘内で BossLab lab で測れる）が、余地が無いので割に合わない | 小 |

第一候補は報酬選択。Skill/Block を採る余地が、Skill の少ない run に集中して残っている。ポーションは使い切
っており採り得る余地が無い。昇格は休んだ選択の大半が低 HP で妥当で、明らかな手落ちは少数。

## 1. 報酬選択（card_reward、Act 3 進入まで）

Block 札は Skill 型で代用した（leader 棚卸しも Skill を Block の主とみなしている）。各 reward は 3 枚提示
から 1 枚採り 2 枚捨てる。採った/捨てたの内訳（45 run 合計）:

| 型 | 採った | 捨てた |
| --- | --- | --- |
| Skill | 195 | 460 |
| Attack | 171 | 772 |
| Power | 69 | 206 |

Queen 戦入場デッキの Skill 枚数の中央値は 10。中央値未満（Skill 5〜9）の run 9 本で、報酬に出た Skill（Block）
札のうち **98 枚を取らなかった**（提示された Skill 131 枚のうち採った 33、捨てた 98。run あたり 7〜15 枚）。
Skill が少ないデッキで、まさに Block 札を多数捨てている。採った枚数が提示を下回るのは、Skill を避けて
Attack/Power を選んだ選択が繰り返されているためで、それが正解だったかは数では言わない。

## 2. 昇格（rest phase、Act 3 進入まで）

campfire の選択内訳（45 run 合計）: SMITH（強化）156 回、HEAL（回復）144 回、HATCH 9 回。強化は既に多く
使っている。強化に使えた（SMITH は常に出る）のに回復を選んだ HEAL が 144 回。そのときの HP 中央値は 59
（範囲 8〜89）で、大半は HP が低く回復が妥当な状況。HP 80 以上で強化を捨てて回復した明らかな手落ちは **3 回** のみ。
Queen 戦入場時点で未強化の札は中央値 17（範囲 6〜26）と多いが、これは回復が要る状況で campfire を回復に
割いた結果でもある（Queen 戦 33 run の 32 が回復選択を含む）。余地は 3 回の明らかな手落ちと、144 回の
回復/強化のトレードオフ（中央値 HP59 で判断が割れる）に限られる。

## 3. ポーション（Queen 戦）

Queen 戦入場時のポーション所持は中央値 3、Queen 戦闘での使用は中央値 3（使い切っている）。ポーションを 1 つ
以上持って Queen 戦で 1 つも使わずに死んだ run は **0**（Queen 戦で敗北 32 run のうち該当 0）。ポーションの
余地はほぼ無い。使用タイミングの最適化余地も、使い切り率の高さから小さい。

## 方法の注記

- Act 3 進入以前 = trace の `run.act==2` の最初の記録より前の事象。reward/rest の選択はその行の `card_index`/
  `option_id` で採用、提示一覧 `cards` から捨て札を数えた。rest の `option_id` は SMITH/HEAL/HATCH（回復=HEAL）。
- ポーション使用は Queen 戦闘行で `potion_id` が付いた行動を数えた。死亡有無と所持数は act3_fullrun_report.py の
  入場/踏破/死亡判定と同じ trace 由来の値。
- 完走 run だけ（runmeta/manifest 揃い）。走行中の `astra_ctrl_v24` は本スキャンの対象外（v23 のみ）。
- 数値は観測した回数の合計で、採否や因果の判断は含まない。
