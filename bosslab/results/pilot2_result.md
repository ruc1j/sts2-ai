# PILOT-2: 負けロールアウトの評価値が探索の順位に与える影響

ゲームは起動せず、main の方針コードも変更していない（候補は別ブランチ）。解析は再生日志のみ。

## 1. 仮説の検証

仮説: `search` の負けロールアウトは `-1 + 0 + immediate` で、敵のHP削りが値に入らない。ほぼ全ロールアウトが負ける戦闘では、探索は `_step_score` の1手読みに縮退する。

方法: `astra_ctrl_v23`+`v24` の2,225決定を標本にし（Queenは各戦最大10、INSATIABLE/VANTOMは各戦最大3、その他は無作為300）、記録済み観測を `rollout_choice` に通して探索を再生した。標本は2,130決定が有効（残り95は合法手が1つだけで探索を経由しない）。

再生の忠実性: `decision_source=rollout_success` の1,290決定のうち、再生した1位の値と記録値が1e-9以内で一致したのは1,123（差の中央値0、最大1.64）。

「immediateだけで選んだ1位」= 各手の `_step_score + _setup_bonus` だけが最大の手。これと探索の1位が一致する割合:

| 区分 | 決定数 | 一致率 | 値の中央値 | ロールアウト勝率中央値 | 1位と最下位の値差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全体 | 2,130 | 79.0% | -0.06 | 0.24 | — |
| QUEEN | 545 | **94.5%** | -0.89 | 0.00 | 0.02 |
| INSATIABLE | 512 | 76.6% | -0.55 | 0.07 | 0.06 |
| VANTOM | 785 | 66.5% | +1.00 | 0.74 | 0.05 |
| その他 | 288 | 88.2% | +1.66 | 1.00 | 0.03 |
| 値 < -0.6 | 901 | 89.6% | -0.88 | 0.00 | 0.03 |
| 値 >= -0.6 | 1,229 | 71.3% | +1.22 | 0.90 | 0.06 |

Queen戦の内訳: 全手のロールアウト勝率が0の決定が513/545（94.1%）。その一致率は**96.9%**。値<-0.6の層でも95.7%。1位と2位の平均値の差は中央0.02で、immediate項（`_step_score/100`）の差そのもの。

結論: 仮説は支持された。Queen戦では探索はほぼ常に「immediateの1手読み」に縮退している。合算1位になる「勝ち筋が見える」決定は545中32（5.9%）しかない。

設計意図の確認: `CODEWIKI.md:279` は「初手ぶんの `_step_score` 加算」を意図的な設計と明記している。`docs/codewiki/2026-09.md` には、探索の試行数を100→200に増やすと8 seed合計で勝数が101→96に悪化した記録があり、「平均的な打ち回しの見積もりが正確になるほど勝ち筋の分散を捨てる」と解釈されている。つまり今回の測定は、意図された副作用がQueen戦でほぼ常時発動していることを示している。敵HP削りを値に入れる変更の記録は docs には見当たらない（`_step_score` の砂creditの重み変更は実走悪化で不採用、CODEWIKI:162）。

## 2. 候補の実装

- ブランチ `cand/rollout-progress`、worktree `~/.sts2/wt-clear5a`（baseは main 43f0e09）。
- 変更は `combat.py` のみ。C# と DLL は対照と同じ。
- 負けロールアウト（`state.player_hp <= 0`）の値に `0.9 × 進捗` を足す。進捗は `_rollout_progress`: 各敵の最大HP（モンスターJSONの `MaxInitialHp`）に対する削り割合を、主敵を1.0、それ以外を0.5で加重平均し、0〜1にクランプ。判断時点のHPではなく最大HP基準。
- 勝ち（1以上）と時間切れ（0）の順序を保つため、負けの上限は -1+0.9 = -0.1。
- 重み `ROLLOUT_LOSS_PROGRESS = 0.9` は調整しない。

## 3. 局所確認（同じ観測で旧版と候補版）

600決定（Queen 300、INSATIABLE 120、VANTOM 120、その他 60）を両版で再生。

| 指標 | 旧版(main) | 候補版 |
| --- | ---: | ---: |
| 例外 | 0/600 | 0/600 |
| 1判断の所要時間（平均） | 2.068s | 2.071s（+0.003s） |
| Power札を選ぶ決定 | 29/600 (4.8%) | 28/600 (4.7%) |
| 決定が変わった割合 | — | 49/600 (8.2%) |

種別ごとの変化: QUEEN 36/300 (12.0%)、INSATIABLE 6/120 (5.0%)、VANTOM 6/120 (5.0%)、その他 1/60 (1.7%)。Queen 300決定のうちPower札の選択は12→11で、増えていない。入れ替わりは攻撃札同士（例: POMMEL_STRIKE→BASH、EVIL_EYE→THUNDERCLAP）が中心。

読み: 進捗項は「HPを多く削る手」を好むので、後で効くPower札を選ぶ方向には働かない。Strength札の価値が見えるようになる、という当初の狙いは、この形では満たされていない。

## 4. テスト

`python3 -m unittest discover -p 'test_*.py'` を候補worktreeで実行: 860件中859件成功、1件エラー。

- `test_official_agent.OfficialAgentTest.test_rollout_sanitizes_a_synthetic_bridge_reported_move`
  - 症状: `ValueError: rollout target is not legal: card:0@1`（`official_agent._map_rollout_card_action`）
  - 原因: このテストは合法手を `target_id=1` に限った合成観測を渡す。進捗項が入ると探索はHPの低い方（Obscura）を狙う手を1位に選び、モデル上は合法だがブリッジの合法手に無い対象になる。実trace 600決定では例外0件で、この形は「合法手がモデルより狭い」合成局面に限られる。
  - テストは変更していない。実機では同じ例外が `choose` のフォールバック（ValueError）でヒューリスティックに落ちるため、クラッシュはせず静かに方針が変わる。

## 5. 留保

- 指標は探索の内部順位であり、勝敗への効果は測っていない。フルrunで測る必要がある。
- 標本は各戦最大10決定で、ターン前半に偏る。
- 再生の一致率は87%（1,290中1,123）。一致しない13%は状態再構築の差で、値の水準は同じ範囲。
